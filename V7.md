# v7

Breaking changes waiting for the next major release. Every published crate shares the 6.x
line, and Cargo treats any 6.x as compatible with any other, so anything here would break
an adopter's `cargo update` if it shipped sooner. `mise run lint:semver` catches the ones
that reach a pull request.

When a change can't go out without breaking the public API, ship the part that doesn't
break now and add the rest here: what changes, why, and what adopters should do.

## usage-argv / usage-rs

### Hide the fields of `FlagMeta`, `CommandMeta` and `ArgMeta`

Mark every field `#[doc(hidden)]` and document the getters (`flag.env_fallback()`,
`cmd.about()`, `arg.help()`, …) as the only read API. The fields stay `pub` because derived
code builds these structs with literals in the adopter's crate. For the same reason the
structs can't be `#[non_exhaustive]`.

**Why:** 6.11.1 moved 35 fields from `FlagMeta` into `FlagExtra` to shrink the tables, which
broke code reading `flag.env_fallback` ([#1489](https://github.com/jdx/usage/issues/1489)).
Once the fields are hidden, table layout is an internal detail and cargo-semver-checks
stops treating field moves as breaking.

**Migration:** replace field reads with the getter of the same name: `flag.env_fallback`
becomes `flag.env_fallback()`. The getters already exist in 6.x.

## usage-cli

### Consider removing `usage generate fig`

Drop the command, or keep it only if a maintained tool turns out to load user-supplied Fig
specs.

**Why:** Fig shut down in 2024. The tools that still read its format (Kiro CLI, formerly
Amazon Q; inshellisense; Warp) only use specs bundled from `withfig/autocomplete`, which
stopped being updated in May 2025, and none documents loading a spec from elsewhere. The
generator has no known consumer, yet every spec feature (such as `choices run=`) still has to
be mapped onto it and kept in step with `usage complete-word`.

**Migration:** use `usage generate completion <shell>` for bash, zsh, fish, or PowerShell.
